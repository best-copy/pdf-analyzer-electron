# 스타일 프로파일 — "이 사람이 만든 것 같은" 결과물 재현 가이드

> 실제 작업 이력에서 역설계한 사용자(인쇄소 운영자·개발 총괄)의 스타일.
> 다른 AI 모델이 이 문서만 보고도 동일한 톤·판단·마감 품질을 재현하는 것이 목표다.

## 1. 한 문장 요약

**"인쇄소 작업대 위의 도구"** — 화려함보다 실무 흐름(분석→변환→임포징→재단→과금)이 끊기지 않는 것, 결과물이 프린터와 재단기에서 그대로 통하는 것을 최우선으로 하는 스타일.

## 2. 시각 아이덴티티

| 요소 | 규칙 | 근거(실측) |
|---|---|---|
| 팔레트 | **Black & Yellow 2색 체계** — 검정 `#1d1d1f`, 노랑 `#ffd60a`, 보조회색 `#48484a`, 옅은노랑 배경 `#fff8db` | 로고·버튼·토글·진행바·메시지창 전부 이 팔레트로 통일 요청 |
| 주행동 버튼 | 노랑 바탕 + 검정 글자 (적용·저장) / 검정 바탕 + 노랑 글자 (다운로드·보조) | |
| 아이콘 | 이모지 사용하되 **무채색**(grayscale). 컬러 이모지가 섞이면 지적함 | "작은 아이콘들의 색상들도 모두 black&yellow로" |
| 상태 표시 | 하단 중앙 고정 토스트 + 노랑 그라데이션 진행바 + % 숫자. 완료 시 사라짐 | 직접 지정한 사양 |
| 강조 표식 | 컬러 페이지=노란 테두리, 현재 위치=아우터 글로우(색 겹침 회피) | 겹치면 구분 안 된다고 수정 요청 |
| 질감 | 둥근 모서리(8~14px), blur 배경 토스트, 카드형 그룹핑 | |

**재현 규칙**: 새 UI를 만들 때 색을 고르지 말 것. 위 4색 안에서만. 제3의 색(파랑·초록·빨강)은 등장 즉시 이질감으로 지적받는다(파괴적 액션의 빨강도 검정으로 교체됨).

## 3. UX 라이팅 (한국어)

- **버튼**: `이모지 + 명사(구)` — "📖 임포징 PDF 생성", "🧾 프린터 판정", "✔ 적용"
- **완료 메시지**: `결과 요약 — 수치` + 줄바꿈 + `실무 지침`. 예:
  > 📖 정합(Cut&Stack) PDF 저장 완료 — 시트 25장 · 2분할 · 묶음당 50쪽
  > 인쇄: 양면 · 가로 용지 · '짧은 쪽 넘김' → 재단 → 왼쪽 묶음을 오른쪽 묶음 위에 겹치면 페이지 순서 완성
- **툴팁**: 짧은 라벨 + title 속성에 상세(왜 필요한지, 권장값). 예: 밀림보정 title="장당 mm (보통 0.1~0.3, 두께에 따라)"
- **경고**: 막지 말고 알려주기 — "⚠ 블리드가 거터의 절반보다 큽니다 — 거터를 6mm 이상 권장" (생성은 해줌)
- **용어**: 번역투 금지, 현장 용어 그대로 — 중철, 정합, 거터, 블리드, 재단선, 밀림보정, 좌철/우철, 짧은 쪽 넘김, 리치블랙, 잉크 정규화, 부(部)

## 4. 제품 판단 기준 (의사결정 재현)

1. **기본값 = 실무에서 매번 켜는 값.** 잉크 정규화 기본 ON, 정합 기본 양면. "자주 쓰는 걸 기본으로" 사고방식.
2. **삭제보다 개선.** 문제가 있어도 "원본대로 되게 하거나, 어려우면 삭제 *의논*" — 먼저 고치는 안을 원한다. 기능 제거는 최후 수단.
3. **원본 충실도 > 보정.** 이미지 밝기·계조는 "원본 그대로"가 정답. 임의 보정(감마, 톤 커브)을 넣지 말 것.
4. **속도는 체감 기준.** 진행률이 특정 구간(85%, 90%)에서 머무는 것 자체를 문제로 본다 — 실제 시간과 별개로 "멈춘 듯 보임"을 없애야 한다(진행률 합류, 프리웜).
5. **화면에서 바로 확인.** 생성/적용 결과는 저장만 하지 말고 즉시 화면에 표시. "적용된 화면이 보이게".
6. **상용 도구가 레퍼런스.** Quite Imposing, Acrobat, 실제 프린터 과금기 — "그 도구처럼 작동"이 스펙이다. 자체 해석으로 규격을 바꾸지 말 것.
7. **부수 산출물 관리에 민감.** 임시파일 자동 정리, 저장 안 한 작업 종료 경고, 최근 파일 — 작업대가 지저분해지는 것을 싫어함.

## 5. 협업 스타일 (요청을 읽는 법)

- **짧은 명령형 한국어, 한 메시지에 3~5개 요구.** 각 문장이 독립 태스크다. 전부 처리하고 항목별로 보고할 것.
- **증거 첨부형.** 스크린샷·원본 파일·상용 도구 설정을 첨부한다. 첨부물이 곧 스펙이므로 말보다 첨부물을 우선 해석.
- **오귀인(엉뚱한 기능 탓)이 가끔 있다.** 예: 변환 밝기 문제를 진단 기능 탓으로. **정중히 사실을 바로잡고 실제 원인을 고치면** 만족한다. 사용자의 전제를 그대로 받아 애먼 기능을 삭제하지 말 것.
- **"의논하고 결정할게"** = 실행 전 보고 요청. 단, 사용자가 이미 선호안(A안)을 밝혔고 그것이 구현 가능하면 A안을 구현하며 보고하는 것을 환영한다.
- **검증 문화**: "~되는지 확인해줘", "비교해 보고 적용해줘" — 증거(렌더 이미지, 수치 비교표) 없는 완료 보고는 신뢰하지 않는다.
- **후속 우선순위 좁히기**: 큰 기능을 받으면 "그중 X와 Y가 주요 기능이야"로 무게중심을 알려준다 — 이때 X·Y를 깊게 파고 나머지는 유지 수준으로.

## 6. 품질 마감선 (이 사람 결과물의 특징)

- 순서·방향이 걸린 로직(임포징 등)은 **번호+색띠 합성 문서를 렌더링한 이미지**로 증명돼 있다.
- 색·계조는 **레퍼런스 렌더러(GS) 대비 수치 오차**로 확정돼 있다.
- 실패해도 죽지 않는다 — 폴백 경로(근사 디코드), 항목별 실패 허용(가져오기), 명확한 오류 문구("여백·거터가 시트보다 큽니다").
- 성능 작업엔 **채택/제외 비교표**가 따라온다.
- 모든 변경은 포터블 앱까지 반영돼 "지금 바로 실행해 확인 가능"한 상태로 끝난다.

## 7. 재현 체크리스트 (다른 AI용)

```
□ 색: #1d1d1f/#ffd60a/#48484a/#fff8db 외 새 색 없음, 이모지 무채색
□ 문구: 한국어 현장 용어, 완료 메시지에 수치+실무 지침
□ 기본값: 실무 최빈값으로 ON
□ 결과: 생성 즉시 화면 표시 + 파일 저장
□ 증거: 렌더 이미지/수치 비교를 보고에 포함
□ 오류: 막기보다 경고+권장값, 실패는 폴백
□ 배포: win-unpacked 동기화까지
□ 사용자 전제가 틀렸으면 사실을 바로잡고 진짜 원인 수정
```
