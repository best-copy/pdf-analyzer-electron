# 프롬프트 템플릿 라이브러리 — 프로그램 개발용

> 이 프로젝트에서 실제로 좋은 결과를 냈던 요청 패턴을 **모델 불문 재사용 가능한 템플릿**으로 정리했다.
> `{중괄호}`는 채워 넣는 자리. 각 템플릿의 "실전 예"는 이 프로젝트에서 실제로 성공한 요청이다.

---

## 공통 원칙 (모든 템플릿에 적용)

프롬프트 앞에 붙이는 **공통 헤더**:

```
[컨텍스트]
- 프로젝트: {프로젝트 경로} — CLAUDE.md(프로젝트 지침)를 먼저 읽고 따를 것
- 완료 기준: 코드가 그럴듯한 것이 아니라 "실행·렌더링으로 검증된 결과"만 완료로 인정
- 배포: 변경 파일을 포터블 앱(win-unpacked)에 동기화까지 해야 완료
```

**효과가 검증된 습관 3가지**
1. **증상은 파일로 첨부** — 말로 설명하는 것보다 원본+문제 산출물 파일, 스크린샷을 주면 원인 도달이 몇 배 빠르다.
2. **참조물 제공** — "이 XML(상용 도구 설정)처럼 작동해야 해"처럼 정답 참조를 주면 규격 해석 오류가 사라진다.
3. **한 메시지에 여러 요구 OK, 단 각 요구는 한 문장으로 완결** — "A하고, B는 C처럼, D는 확인해줘" 형태가 잘 동작한다.

---

## T1. 새 기능 추가 (도메인 실무 기능)

```
[역할] 너는 {도메인} 실무에 밝은 시니어 개발자다.
[요구] {기능명}을 추가해줘.
- 사용 흐름: {누가, 언제, 왜 쓰는지 한 줄}
- 입력/옵션: {옵션 목록 — 실무 기본값 명시}
- 출력: {산출물 형식, 파일명 규칙, 완료 메시지에 넣을 실무 지침}
[제약]
- 기존 {관련 기능}과 UI 패턴·옵션을 공유할 것
- 핵심 계산은 순수 함수로 분리해 단독 테스트 가능하게
[검증] 실제 산출물을 렌더링한 이미지로 {정답 조건}을 보여줘.
```

**실전 예 (성공)**: "인쇄소 실무와 직결되는 임포징 기능을 추가해줘" → 후속으로 "2up과 cut&stack이 주요 기능이야" — 큰 요청 후 우선순위를 좁혀주는 2단계 패턴이 효과적이었다.

**나쁜 변형**: 옵션·기본값 없이 "임포징 넣어줘"만 하면 실무와 다른 기본값이 나온다. 기본값은 반드시 명시하거나 "실무에서 가장 흔한 값을 기본으로" 라고 지시.

## T2. 버그 분석·수정 (원인 불명 결함)

```
[역할] 너는 {영역} 디버깅 전문가다. 추측으로 고치지 말고 원인을 증명한 뒤 수정해라.
[증상] {한 줄 관찰. 예: "페이지 속 모든 이미지가 반전된 것처럼 보인다"}
[첨부] 원본 파일 + 문제 산출물 파일 (재현 입력 그대로)
[요구]
1. 원인을 분석해 먼저 보고 (어느 단계, 왜)
2. 수정
3. 같은 입력으로 수정 전/후 비교 증거 (렌더 이미지 or 수치)
[제약] 관련된 다른 경로(예: 정상이던 3comp 경로)가 깨지지 않았는지 회귀 확인 포함.
```

**실전 예 (성공)**: CMYK JPEG 반전·밝기 버그 — 원본+변환본 PDF 2개를 첨부하고 "변환오류를 찾아 수정해줄래?"라고 요청 → 원인(디코더 관례 차이) 증명 → 정답 기준 캘리브레이션으로 공식 확정.

**핵심 지시어**: 계조·색·좌표처럼 "정답이 존재하는" 문제는 다음 문장을 추가하라.
> "추측으로 공식을 고르지 말고, 신뢰할 수 있는 기준(레퍼런스 렌더러 등)과 픽셀/수치 대조로 후보를 비교해 확정해라."

## T3. UI/테마 일괄 변경

```
[역할] 너는 UI 일관성에 집착하는 프론트엔드 개발자다.
[요구] {범위: 화면 전체/특정 패널}의 {대상: 색·아이콘·버튼}을 {테마 정의}로 통일해줘.
- 테마: 주색 {hex}, 강조 {hex}, 예외 {가독성 예외 규칙}
[제약]
- 활성/hover/disabled 상태까지 전부
- 컬러 이모지는 무채색화(가독성 나쁜 곳은 개별 처리)
- 기능·레이아웃 변경 금지, 색만
[검증] 남은 이색 요소가 없는지 색상값 전수 검색으로 확인했다고 보고.
```

**실전 예 (성공)**: "화면에 보이는 작은 아이콘들의 색상들도 모두 black & yellow로 해줘. 사이드바도 동일하게." — 범위를 "사이드바도"처럼 명시하면 누락이 없다. 스크린샷을 첨부하면 더 정확.

## T4. 성능 최적화

```
[역할] 너는 성능 엔지니어다. 병목을 측정·특정한 뒤에만 손대라.
[요구] {구간}(예: 분석, 다운로드 85%~완료 구간) 속도를 최대로 올려줘.
[방법]
1. 가능한 방법들을 조사해 효과/위험 비교표로 먼저 제시
2. 정확도·안정성을 해치지 않는 것만 적용
3. 무엇을 채택하고 무엇을 왜 제외했는지 보고
[제약] 판정 정확도(예: 컬러 감지)는 절대 저하 금지.
```

**실전 예 (성공)**: "PDF 분석속도를 더 올릴 수 있는 방법을 찾아 비교해 보고 적용해줘" — "비교해 보고"라는 한 마디가 무분별한 변경 대신 근거 있는 선택을 끌어낸다.

**특화 패턴 — 구간 지목**: "다운로드 최적화 구간 중 90% 구간에서 시간이 많이 소요되고 있어" 처럼 **진행률 구간을 지목**하면 병목 특정이 즉시 된다.

## T5. 구조 리팩터링

```
[역할] 너는 리팩터링 전문가다. 동작 변화 0을 보장해라.
[요구] {대상}을 {구조}로 분리/정리해줘.
[방법]
- 분리 전, 깨질 수 있는 지점(로드 순서·전역 참조·초기화 호출)을 전수 조사해 보고
- 이동만 하고 로직 수정 금지 (수정할 게 보이면 별도 목록으로 보고)
[검증] 부팅 + 콘솔 오류 0 + 주요 흐름 1회 통과. 새 구조의 규칙(뭘 하면 깨지는지)을 지침 문서에 기록.
```

**실전 예 (성공)**: 7,300줄 index.html → css+js 3분할. 성공 요인은 "분리 전에 최상위 즉시 실행문 전수 조사"를 시킨 것.

## T6. 자체 평가·로드맵 요청

```
[역할] 너는 이 프로그램의 수석 아키텍트이자 냉정한 감사관이다.
[요구] 스스로 이 프로그램을 평가하고 다음을 보고해줘:
1. 알려진 결함/위험 (우선순위·근거 포함)
2. 보완할 부분
3. {도메인} 실무 가치가 큰 신규 기능 제안 (가치 요약 표)
4. 구조/장기 과제
나와 상의 후 진행하자. 네 권장 순서도 제시해.
```

**실전 예 (성공)**: "너 스스로 이 프로그램을 평가하고 … 보고해줘. 나와 상의 후 진행하자." → 보고서 → 사용자가 순서 지정("D 먼저, A2·A1·C1 순") → 순차 실행. **보고와 실행을 분리**하는 것이 핵심.

## T7. 참조물 기반 기능 복제 (역설계)

```
[역할] 너는 규격 역설계 전문가다.
[첨부] {상용 도구의 설정 파일/출력물/스크린샷}
[요구] 첨부처럼 {기능}이 작동해야 해. 참조를 해석해서 동일 규칙으로 구현해줘.
[검증]
- 참조 규칙 해석 결과를 먼저 설명 (예: "1 1* 2* 2 = 각 페이지 2벌, *는 180°")
- 구현 결과를 렌더 이미지로 참조와 대조
```

**실전 예 (성공)**: Quite Imposing XML 첨부 + "첨부한 xml파일처럼 2up 임포징이 작동되어야 하니까 참고해서 기능 생성해줘" → 규칙 해석 → 순수 함수 구현 → 색띠 합성 PDF 렌더로 방향 검증.

## T8. 기능 유지/삭제 의사결정 상담

```
[상황] {기능}에 {문제}가 있어.
[선택지] {대안 A}가 가능하면 그렇게 하고, 구현이 어려우면 {대안 B(삭제 등)}로 할지 너와 의논하고 결정할게.
```

**실전 예**: "원본 밝기 그대로 적용되게 하거나 기능구현이 어려우면 프린터 판정 기능은 삭제하는게 어떨지 의논하고 결정할게." — AI가 오해(엉뚱한 기능 지목)를 바로잡고 실제 원인을 고치는 여지를 준다. **삭제를 기본값으로 두지 말고 조건부로 두는 것**이 좋은 결과를 낳는다.

---

## T9. 반복 유지보수 묶음 (일상 요청)

```
다음을 처리해줘:
1. {소규모 UI 수정 — 위치·색·문구}
2. {버그 — 증상 + 재현 조건 한 줄}
3. {확인 요청 — "…이 되는지 확인해줘"}
각각 처리 후 무엇을 어떻게 했는지 항목별로 보고해.
```

**팁**: 확인 요청("임시파일이 자동 정리되는지 확인해줘")을 섞으면 AI가 코드를 읽고 보증하거나 고친다 — 테스트를 공짜로 얻는 패턴.

## 부록: 검증 요구 문구 모음 (복사해서 사용)

- "실제 산출물을 렌더링한 이미지로 보여줘."
- "수정 전/후를 같은 입력으로 비교해줘."
- "추측 금지. 신뢰 기준과 수치 대조로 확정해."
- "기존 {경로}가 깨지지 않았는지 회귀 확인 포함해."
- "방법들을 비교표로 제시하고 채택/제외 이유를 밝혀."
- "핵심 로직은 순수 함수로 분리해 단독 테스트 가능하게."
